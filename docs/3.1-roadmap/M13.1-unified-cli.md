# M13.1: Unified CLI Architecture

**Status**: Design Phase
**Created**: 2025-11-29
**Target**: Pulse 3.1.0

## Current State

### Entry Points
- Main binary: `bin/pulse` (dispatcher)
- Secondary binary: `bin/pulselang` (alias to pulse)
- Legacy runner: `lib/run.js` (used by npm scripts, bypasses CLI)

### Command Structure
All commands are implemented as standalone files in `bin/`:
- `bin/pulse-run.js` - Compile and execute .pulse files
- `bin/pulse-dev.js` - Development server with file watching
- `bin/pulse-test.js` - Test runner
- `bin/pulse-prs.js` - Pulse Runtime Server
- `bin/pulse-add.js` - Add package
- `bin/pulse-remove.js` - Remove package
- `bin/pulse-install.js` - Install dependencies
- `bin/pulse-lsp` - LSP server proxy (NOT in dispatcher)

### Issues
1. `bin/pulse` dispatcher has hardcoded version comment (v1.5.0, outdated)
2. `pulse lsp` command exists but is not routed through main dispatcher
3. `lib/run.js` duplicates compilation logic from `bin/pulse-run.js`
4. No unified command module - each command is a separate script
5. Inconsistent flag parsing across commands
6. No shared utilities for common operations (compilation, error handling)

## Target Architecture

### Unified Module Structure

```
lib/cli/
├── main.js                    # Main CLI entry (bin/pulse imports this)
├── commands/
│   ├── run.js                 # pulse run
│   ├── dev.js                 # pulse dev
│   ├── test.js                # pulse test
│   ├── prs.js                 # pulse prs (Pulse Runtime Server)
│   ├── lsp.js                 # pulse lsp (Language Server)
│   ├── add.js                 # pulse add
│   ├── remove.js              # pulse remove
│   └── install.js             # pulse install
├── utils/
│   ├── compile.js             # Shared compilation utilities
│   ├── parse-args.js          # Argument parsing
│   ├── error-handler.js       # Consistent error reporting
│   └── version.js             # Version information
└── README.md                  # CLI architecture documentation
```

### Entry Point Flow

```
bin/pulse (thin shim)
  ↓
lib/cli/main.js (dispatcher + help)
  ↓
lib/cli/commands/<command>.js
  ↓
Shared utilities (lib/cli/utils/*)
```

### Design Principles

1. **Thin Binaries**: `bin/pulse` and `bin/pulselang` are minimal shims that import `lib/cli/main.js`
2. **Unified Compilation**: Single `lib/cli/utils/compile.js` used by `run`, `dev`, `test`
3. **Consistent Interface**: All commands use shared argument parsing and error handling
4. **Backward Compatible**: Existing command syntax and flags remain unchanged
5. **Internal Consolidation**: `lib/run.js` becomes a thin wrapper over `lib/cli/utils/compile.js`

## Compatibility Guarantees

### Commands (Must Keep Working)
- `pulse run <file>` - No behavior change
- `pulse dev` - No behavior change
- `pulse test [pattern]` - No behavior change
- `pulse prs` - No behavior change
- `pulse add <package>` - No behavior change
- `pulse remove <package>` - No behavior change
- `pulse install` - No behavior change
- `pulse lsp` - Must be added to dispatcher (currently separate)
- `pulse --version` / `pulse -v` - No behavior change
- `pulse --help` / `pulse -h` - No behavior change

### Flags (Stable in 3.1)
**pulse run**:
- `--sourcemap` / `--source-map`
- `--strict-ast`
- `--strict-semantic`
- `--strict-types`
- `--legacy-backend`

**pulse dev**:
- `--port <number>`
- `--watch <dir>`

**pulse test**:
- `<pattern>` (file pattern)

**pulse prs**:
- `--port <number>`

**pulse lsp**:
- (stdio-based, no flags)

### Internal Scripts (npm)
These scripts must continue to work:
- `npm test` → `bash scripts/verify-release.sh`
- `npm run docs` → Uses `lib/run.js` internally
- Other internal scripts may use `lib/cli/utils/compile.js` or `lib/run.js` (which wraps it)

## Migration Strategy

### Phase 1: Create Unified Structure (No Behavior Change)
1. Create `lib/cli/` directory structure
2. Create `lib/cli/utils/compile.js` (extract from `bin/pulse-run.js`)
3. Create `lib/cli/utils/parse-args.js` (shared argument parsing)
4. Create `lib/cli/utils/error-handler.js` (consistent error reporting)
5. Create `lib/cli/main.js` (import and adapt current `bin/pulse` dispatcher)

### Phase 2: Migrate Commands
1. Migrate `pulse run` → `lib/cli/commands/run.js`
2. Migrate `pulse dev` → `lib/cli/commands/dev.js`
3. Migrate `pulse test` → `lib/cli/commands/test.js`
4. Migrate `pulse prs` → `lib/cli/commands/prs.js`
5. Add `pulse lsp` → `lib/cli/commands/lsp.js` (move from `bin/pulse-lsp`)
6. Migrate `pulse add` → `lib/cli/commands/add.js`
7. Migrate `pulse remove` → `lib/cli/commands/remove.js`
8. Migrate `pulse install` → `lib/cli/commands/install.js`

### Phase 3: Update Entry Points
1. Refactor `bin/pulse` to import `lib/cli/main.js`
2. Update `bin/pulselang` (ensure it's an alias)
3. Refactor `lib/run.js` to use `lib/cli/utils/compile.js`
4. Remove old `bin/pulse-*.js` files

### Phase 4: Verification
1. Run `npm test`
2. Run `bash scripts/verify-release.sh`
3. Test all commands manually:
   - `pulse run examples/hello.pulse`
   - `pulse dev`
   - `pulse test`
   - `pulse prs`
   - `pulse lsp`
   - `pulse add <package>`
   - `pulse --version`
   - `pulse --help`
4. Verify internal npm scripts work

## Testing Requirements

### Unit Tests
- `lib/cli/utils/compile.js` - Compilation with all flags
- `lib/cli/utils/parse-args.js` - Argument parsing edge cases
- `lib/cli/utils/error-handler.js` - Error formatting

### Integration Tests
- Each command in `lib/cli/commands/` with real .pulse files
- Verify flag combinations work correctly
- Verify error messages are consistent

### Regression Tests
- All existing `npm test` suites must pass
- `scripts/verify-release.sh` must pass
- Internal scripts (docs build, etc.) must work

## Success Criteria

M13.1 is complete when:
1. All commands route through unified `lib/cli/main.js`
2. All commands use shared utilities (`compile.js`, `parse-args.js`, `error-handler.js`)
3. `pulse lsp` is in the main dispatcher
4. `lib/run.js` delegates to `lib/cli/utils/compile.js`
5. All tests pass without modification
6. No user-visible behavior changes
7. Documentation updated to reflect new architecture
